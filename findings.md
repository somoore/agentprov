## Residual risk

1. **Signing is tamper-evidence, not non-repudiation against the same user.** The keychain item is readable by any process running as the user (documented in `agentprov-integrity` and now in the README/CLI). A true boundary needs a privileged signer / Secure Enclave. The Go `verify` now fails closed and pins out-of-band, which closes the *forgery-on-a-fresh-verifier* path; it does not stop a same-UID attacker who reads the seed.
2. **Loopback viewer (Go):** Host/Origin/method guards + random port block browser rebinding and drive-by renders, and headers stop caching. There is still no per-run token, so a **local** process that learns the port can read `/chain` (which may contain secrets). The Rust viewer's `?t=` token remains the stronger design.
3. **Hook `transcript_path`** is still opened as given (same-user read by contract); only the `session_id` path-component escape is fixed.
4. **Rust temp paths (SEC-09) and unbounded line reads (SEC-12)** are deferred: the Rust viewer is not the shipped `view` path and capping three parsers is a separate change. Go temp handling is fixed.
5. **Committed plugin binary (AP-27)** remains unsigned and unverified by `bootstrap.sh`. The owner must rotate to a signed/checksummed release artifact; a fix branch should not silently break zero-install.
6. **`cargo fmt --check` remains red** on the pre-existing style, so CI deliberately gates on `clippy` + tests instead. A separate formatting commit is required before adding a fmt gate.
7. **No gosec gate**: the 83-row baseline is adjudicated here, but CI does not fail on *new* gosec findings; adding a baseline mechanism is follow-up work.
8. **No secrets found** in tracked files or history; nothing to rotate. The gitleaks hits were dependency build metadata (FP-05).
9. **CI was added but not executed on GitHub** in this environment; every command the workflow runs was executed locally and passed (G1–G5).
